# Σύστημα Υβριδικής Ανάκτησης Πληροφορίας και Παραγωγής Απαντήσεων (Hybrid RAG) για Πολυ-Μαθησιακά Ακαδημαϊκά Δεδομένα

**Πτυχιακή Εργασία**

---

## 1. Εισαγωγή και Σκοπός της Εργασίας

Η παρούσα πτυχιακή εργασία εστιάζει στη σχεδίαση, υλοποίηση και αξιολόγηση ενός προηγμένου συστήματος **Retrieval-Augmented Generation (RAG)**, προσαρμοσμένου στις ειδικές απαιτήσεις της τριτοβάθμιας εκπαίδευσης. Το σύστημα επιτρέπει την αυτόματη επεξεργασία ακαδημαϊκού υλικού (διαφάνειες, σημειώσεις, έγγραφα PDF και TXT) για πολλαπλά πανεπιστημιακά μαθήματα και παρέχει έγκυρες, τεκμηριωμένες απαντήσεις σε φυσική γλώσσα.

Βασικοί στόχοι της εργασίας:
1. **Αντιμετώπιση Πολυτροπικού Περιεχομένου:** Αυτόματη εξαγωγή και κατανόηση μη κειμενικών στοιχείων (διαγράμματα οντοτήτων-συσχετίσεων ER, αρχιτεκτονικά διαγράμματα, μαθηματικοί τύποι, κώδικας) μέσω μοντέλων υπολογιστικής όρασης (Vision LLM).
2. **Υβριδική Αναζήτηση (Hybrid Retrieval):** Συνδυασμός διανυσματικής αναζήτησης (Dense Vector Search) και αναζήτησης λέξεων-κλειδιών (Sparse Keyword Search) για την επίτευξη υψηλής ακρίβειας ανάκτησης σε ελληνικά ακαδημαϊκά κείμενα.
3. **Εξάλειψη Παραισθήσεων (Hallucinations):** Αυστηρός περιορισμός του μοντέλου παραγωγής (Google Gemini 2.5 Flash) αποκλειστικά στο ανακτηθέν πλαίσιο (Strict Grounding Policy).
4. **Πολυ-Μαθησιακή Αρχιτεκτονική (Multi-Course Scalability):** Ανεξάρτητη διαχειρισιμότητα και δεικτοδότηση διαφορετικών ακαδημαϊκών ενοτήτων (π.χ. "Βάσεις Δεδομένων", "Παράλληλος και Κατανεμημένος Υπολογισμός").
5. **Αυτοματοποιημένη Αξιολόγηση (LLM-as-a-Judge):** Ποσοτικός και ποιοτικός έλεγχος της απόδοσης RAG μέσω του μοντέλου Gemma 3 4B σε τρεις άξονες (Faithfulness, Relevance, Context Quality).

## 2. Αρχιτεκτονική και Μεθοδολογία Συστήματος

Το σύστημα αποτελείται από τέσσερα κύρια υποσυστήματα:

### 2.1 Pipeline Επεξεργασίας και Δεικτοδότησης Εγγράφων (Data Ingestion Pipeline)
- **Πολυτροπική Αναγνώριση Εικόνων (Multimodal PDF Processing):** Κατά την ανάλυση των εγγράφων PDF (μέσω PyMuPDF), απομονώνονται οι εικόνες και τα διαγράμματα άνω συγκεκριμένων διαστάσεων. Αυτά αποστέλλονται στο μοντέλο **Google Gemini 2.5 Flash Vision**, το οποίο παράγει λεπτομερή περιγραφή στα Ελληνικά (μεταγραφή διαγραμμάτων ER, σχεσιακής άλγεβρας, κώδικα).
- **Μηχανισμός Persistent Caching (Vision Cache):** Για την αποφυγή περιττών κλήσεων API και τον περιορισμό του κόστους/rate limits, χρησιμοποιείται μνήμη JSON cache με βάση το MD5 hash κάθε εικόνας (`vision_cache.json`).
- **Τμηματοποίηση Κειμένου (Text Chunking):** Τα κείμενα ενοποιούνται σε σημασιολογικά τμήματα (chunks) βάσει ελάχιστου ορίου λέξεων (`MIN_CHUNK_WORDS = 15`), διατηρώντας τη σύνδεση με το έγγραφο πηγής και τον αριθμό σελίδας.

### 2.2 Μηχανισμός Υβριδικής Αναζήτησης (Hybrid Retrieval Subsystem)
Η ανάκτηση συνδυάζει δύο συμπληρωματικές μεθόδους:
1. **Πυκνή Διανυσματική Αναζήτηση (Dense Retrieval):**
   - Μοντέλο Embeddings: `intfloat/multilingual-e5-large-instruct` (1024 διαστάσεις, εξειδικευμένο σε πολυγλωσσικές αναζητήσεις).
   - Βάση Δεδομένων Διανυσμάτων: **ChromaDB** (Persistent Collection ανά μάθημα).
2. **Αραιή Αναζήτηση Λέξεων-Κλειδιών (Sparse Retrieval):**
   - Αλγόριθμος **BM25 (BM25Okapi)**.
   - Εξειδικευμένος Tokenizer Ελληνικών (`tokenize_greek`): Καθαρισμός diacritics/τόνων μέσω Unicode NFD normalization, αφαίρεση σημεία στίξης και μετατροπή σε πεζά.
3. **Συγχώνευση Κατάταξης (Reciprocal Rank Fusion - RRF):**
   Τα αποτελέσματα των δύο μεθόδων συνδυάζονται με βάση τον τύπο:
   $$RRF\_score(d) = \sum_{m \in M} \frac{1}{k + rank_m(d)}$$
   όπου $k = 60$. Τα κορυφαία τμήματα προωθούνται στο μοντέλο παραγωγής.

### 2.3 Παραγωγή Απαντήσεων & Θεμελίωση (LLM Generation & Grounding)
- Μοντέλο Παραγωγής: **Google Gemini 2.5 Flash** (με παράμετρο `temperature = 0` για σταθερές και προκαθορισμένες απαντήσεις).
- Prompt Engineering: Επιβολή αυστηρού κανόνα θεμελίωσης (grounding). Αν οι ζητούμενες πληροφορίες δεν εντοπίζονται στις ανακτηθείσες πηγές, το σύστημα δηλώνει ρητά την αδυναμία εντοπισμού τους, αποτρέποντας την παραγωγή λανθασμένων πληροφοριών.

### 2.4 Πλαίσιο Αξιολόγησης LLM-as-a-Judge (Evaluation Subsystem)
- **Μοντέλο Κριτής:** Χρήση του ανοιχτού γλωσσικού μοντέλου **Gemma 3 (4B Instruct)** με 4-bit quantization (BitsAndBytes NF4) σε περιβάλλον Google Colab GPU.
- **Πολυπαραμετρική Αξιολόγηση (Multi-Criteria Scoring):** Υπολογισμός επιμέρους δεικτών κλίμακας 1–5 για Faithfulness (Πιστότητα), Answer Relevance (Σχετικότητα Απάντησης) και Context Precision/Recall (Ποιότητα Ανάκτησης), καθώς και παραγωγή συνολικού δείκτη (Composite Score).
- **Ανθεκτικότητα Εκτέλεσης (Drive Checkpointing & OOM Guard):** Αυτόματη περιοδική αποθήκευση προόδου στο Google Drive (`evaluation_checkpoint.json`) και μηχανισμός διαχείρισης υπερχείλισης μνήμης GPU (CUDA Out-Of-Memory Recovery).

## 4. Προαπαιτούμενα και Εγκατάσταση

### 4.1 Απαιτήσεις Περιβάλλοντος
- Python 3.10 ή νεότερη έκδοση.
- Google Gemini API Key (μέσω του Google AI Studio).
- Hugging Face Access Token (για τη φόρτωση του Gemma 3 στο notebook αξιολόγησης).

### 4.2 Λήψη Έργου και Δημιουργία Εικονικού Περιβάλλοντος
```bash
git clone https://github.com/USERNAME/rag-project.git
cd rag-project

python -m venv venv
```

Ενεργοποίηση εικονικού περιβάλλοντος:
- Σε περιβάλλον Windows:
  ```powershell
  venv\Scripts\activate
  ```
- Σε περιβάλλον Linux / macOS:
  ```bash
  source venv/bin/activate
  ```

### 4.3 Εγκατάσταση Εξαρτήσεων
```bash
pip install -r requirements.txt
```

### 4.4 Ρύθμιση Μεταβλητών Περιβάλλοντος
Δημιουργήστε το αρχείο `.env` στη ρίζα του έργου με βάση το `.env.example`:
```bash
cp .env.example .env
```
Προσθέστε το κλειδί API στο αρχείο `.env`:
```env

```

## 6. Σύνολο Δεδομένων & Πλαίσιο Αξιολόγησης (RAG Evaluation)

### 6.1 Σύνολο Δεδομένων Αξιολόγησης (`rag_evaluation_data.json`)
Για τις ανάγκες της ακαδημαϊκής αξιολόγησης του συστήματος RAG, οι ερωτήσεις, τα ανακτηθέντα τμήματα κειμένου (Retrieved Contexts) και οι παραχθείσες απαντήσεις καταγράφονται στο αρχείο `rag_evaluation_data.json`.

Το σύνολο δεδομένων υποστηρίζει διάφορους τύπους ερωτήσεων:
- **Factual Recall:** Ανάκληση συγκεκριμένων γεγονότων και ορισμών.
- **Conceptual Understanding:** Εννοιολογική κατανόηση και επεξήγηση.
- **Multi-hop Reasoning:** Σύνθεση πληροφοριών από πολλαπλά τμήματα κειμένου.
- **Unanswerable:** Ερωτήσεις εκτός πεδίου (δοκιμή αντοχής σε παραισθήσεις).
- **Image-based:** Ερωτήσεις που βασίζονται σε μεταγραφές διαγραμμάτων/εικόνων.

### 6.2 Αυτόματη Αξιολόγηση μέσω `rag_evaluation.ipynb` (LLM-as-a-Judge)
Η ποσοτική και ποιοτική αξιολόγηση εκτελείται στο notebook `evaluation/rag_evaluation.ipynb` χρησιμοποιώντας το μοντέλο **Gemma 3 (4B Instruct)**.

**Βασικές Μετρικές Αξιολόγησης (Κλίμακα 1–5):**
1. **Faithfulness (Πιστότητα):** Ελέγχει αν οι ισχυρισμοί της απάντησης τεκμηριώνονται ρητά από τα ανακτηθέντα chunks (εντοπισμός hallucinations).
2. **Answer Relevance (Σχετικότητα Απάντησης):** Αξιολογεί αν η απάντηση καλύπτει άμεσα και στοχευμένα το αίτημα της ερώτησης.
3. **Context Precision & Recall (Ποιότητα Ανάκτησης):** Εξετάζει τη σχετικότητα (Precision) και την επάρκεια (Recall) των ανακτηθέντων chunks.
4. **Composite Score:** Ο μέσος όρος των έγκυρων επιμέρους βαθμολογιών.

**Παραγόμενα Αρχεία & Οπτικοποίηση:**
- `evaluation_results.json`: Αναλυτικά αποτελέσματα, κείμενα ανάλυσης και raw output του κριτή per question.
- `evaluation_summary.csv`: Σύνοψη αποτελεσμάτων σε μορφή πίνακα για στατιστική ανάλυση στο Excel.
- `evaluation_chart.png`: Συγκριτικά γραφήματα μέσων όρων ανά κριτήριο και Composite score ανά κατηγορία ερώτησης.
